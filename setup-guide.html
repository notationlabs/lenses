Lenses — setup guide

Connect a real agent to your real browser. Six steps, roughly five minutes. Tick each step as you go – progress is saved in this page.

Step 1

Build the packages

Open a terminal and run:

cd "/Users/coder/Library/Mobile Documents/com~apple~CloudDocs/Projects/ideas/actors" && pok build

The command builds three things: the lens engine, the MCP server (lens-host), and the Chrome extension. The extension lands in apps/extension/dist.

the last line reports the build output paths, with no errors above it.
No pok? Use pnpm directly
cd "/Users/coder/Library/Mobile Documents/com~apple~CloudDocs/Projects/ideas/actors" && pnpm install && pnpm -r build
Step 2

Load the extension in Chrome

Chrome blocks links to its internal pages, so copy the address and paste it into the address bar yourself:

chrome://extensions
  1. Toggle Developer mode on (top-right of the page).
  2. Click Load unpacked (top-left).
  3. In the file picker, press ⌘⇧G (Go to Folder) and paste this path:
/Users/coder/Library/Mobile Documents/com~apple~CloudDocs/Projects/ideas/actors/apps/extension/dist
  1. Click Select.
a card named Lens Host appears in the extensions list, with no red error badge.
The extension has no popup and no chat window – it is deliberately headless. It sits idle until an MCP host connects on ws://127.0.0.1:4319.
Step 3

Reload any open tabs

Content scripts inject when a page loads, so tabs that were already open before Step 2 are invisible to the extension. Reload the ones you care about (⌘R in each), or just let lens calls open fresh background tabs – they handle themselves.

Step 4

Register the MCP server with Claude Code

Back in the terminal:

cd "/Users/coder/Library/Mobile Documents/com~apple~CloudDocs/Projects/ideas/actors" && pok setup mcp

The command rebuilds, then registers lens-host with Claude Code. Claude Code will spawn the host on demand; you don't run it yourself.

lens-host registered. Open a NEW Claude Code session…
Prefer the raw command, or using a different MCP client?

This is what pok setup mcp runs:

claude mcp add lens-host --env LENS_DIR="/Users/coder/Library/Mobile Documents/com~apple~CloudDocs/Projects/ideas/actors/lenses" -- node "/Users/coder/Library/Mobile Documents/com~apple~CloudDocs/Projects/ideas/actors/packages/host/dist/index.js"

Any MCP client that supports stdio servers and sampling can use the same command and args. Sampling matters: the LLM fallback tier is served by the calling agent's own model, so there is no API key anywhere in this stack.

Step 5

Test it

Open a new Claude Code session (existing sessions won't see the new server) and paste:

what's on the front page of hacker news? use lens_call
Chrome opens a background tab on news.ycombinator.com; the agent answers with the story list, extracted by the DOM tier – no model tokens spent on extraction.

Then try the outcome flow. If you're logged out of GitHub, this returns a structured needs_auth instead of failing:

check my github notifications with lens_call
Step 6

If something misbehaves

Work down this list in order – each check rules out one link in the chain:

  1. Ask the agent to run bridge_status. It reports whether the extension ever connected to the host. "not connected" means the problem is browser-side; connected means the problem is in the lens or the page.
  2. On chrome://extensions, open the Lens Host card and click service worker to see its console. Look for WebSocket reconnect messages – it retries ws://127.0.0.1:4319 with backoff, so a host started later is picked up automatically.
  3. If a call times out on a page you had open before installing: reload that tab (Step 3) and retry the same call.
  4. Run the no-browser demo to confirm everything below the extension is healthy:
    cd "/Users/coder/Library/Mobile Documents/com~apple~CloudDocs/Projects/ideas/actors" && pok demo
    It exercises the MCP handshake, the bridge, sampling, and the cache with a fake extension, and ends with SMOKE OK.
Write lenses are refused by default. To allow them, re-register with pok setup mcp --writes – only do so once you're comfortable that a lens can then fire authenticated requests in your session.
